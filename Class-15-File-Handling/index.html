A program cannot touch storage itself. It asks the operating system.
  • open() is how Python asks. It gives back a file object: your handle to the file.

What encoding='UTF-8' means

  • The file object said encoding='UTF-8'. Storage keeps only numbers (bytes), so Python needs a rule to turn ₹, Sumit or सुमित into numbers and back. That rule is the encoding.
Storage keeps only numbers. The encoding is the rule for turning text into numbers and back.

Modes: quick check

Which mode can never change a file?
"r". Read only. The other three can all create or change a file.
Three opens in a row. What does log.txt hold at the end?
f = open("log.txt", "w")
f.write("A")
f.close()

f = open("log.txt", "a")
f.write("B")
f.close()

f = open("log.txt", "w")
f.write("C")
f.close()
C. "w" writes A. "a" adds B, so AB. The last "w" erases everything and writes C.
Each "w" starts from an empty file.
A loop saves three names. What does paid.txt hold at the end?
for name in ["Sumit", "Vamsi", "Akshay"]:
    f = open("paid.txt", "w")
    f.write(name + "\n")
    f.close()
Only Akshay. Each trip round the loop opens with "w", which erases the file. A real bug that loses data quietly. Fix: use "a", or open once before the loop.
Three writes, one survivor.

Why close a file at all?

  • An open file is a live link between your program and the operating system. close() ends it.
✋
The file is still open when we read it back. What does the first print show?
file = open("receipt.txt", "w")
file.write("Paid 100 to Akshay")
print("[" + open("receipt.txt").read() + "]")
file.close()
print("[" + open("receipt.txt").read() + "]")
[Paid 100 to Akshay]
[]: nothing yet
An error: the file is busy
[] [Paid 100 to Akshay]
  • Writing to storage is slow, so Python collects your writes in RAM first. close() sends them to storage.
  • An open file can stay locked: on Windows, Excel or another program cannot change or delete it.
  • A program may keep only a limited number of files open. Thousands left open: OSError: [Errno 24] Too many open files.
A write is not safe until the file is closed.

Each payment must be added to a history file, and the old ones kept. Which mode?
"a". It keeps what is there and adds at the end. "w" would erase the history every time.

It closes. Always, even when an error stops the block. That is why it is the standard way.

Recap

Two minutes. Three points you would tell a friend who missed today.
  • Memory forgets, storage remembers. Variables live in RAM; a file lives in storage and outlives the program.
