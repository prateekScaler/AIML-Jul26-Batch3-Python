self and methods, in words

What is a method?
A function inside a class. Same def, but it is written in the class body and called on an object: rex.bark(). That object arrives as self.
Is self a keyword?
A convention. Call the first parameter dog and the code still runs. Everyone writes self so that every class reads the same way.
Where do rex.name and rex.age live?
In the object's block. The class holds the code. Each object holds its own data. self.name = name is the write into that block, and it stays after __init__ ends.
A method is a function in a class. self is the object it runs on, by convention. Data lives on the object, code lives on the class.

Class variables, in words

Where does a class variable live?
On the class. Written in the class body, outside any method. Every object reads it through the class, so there is one copy.
rex.species = "Wolf" on one dog. What changes?
Only rex. Assigning on an object makes an instance attribute, which hides the class one for that object. Dog.species and fido.species are unchanged.
Why is tricks = [] in the class body a trap, but species = "Canis familiaris" is fine?
Changed in place. append changes the one shared list. A string never changes in place; writing a new one makes an instance attribute. Shared and changeable together is the trap.
A class variable is one value on the class. Assign through self and that object gets its own. A shared list is one list for all: make lists in __init__.

  • Fifty places in a program can set balance. One typo, one bad line, and the money is wrong.
  • The fix: put the data inside, mark it internal, and make the methods the only door.
class BankAccount:
    def __init__(self, balance):
        self.__balance = balance

    def get_balance(self):
        return self.__balance

    def deposit(self, amount):
        if amount > 0:
            self.__balance += amount

a polite hint only; nothing is hidden

✋

Which call is the point of encapsulation?
deposit. Go through the door that checks. A creates a new, unrelated attribute with no error; B makes a millionaire by reaching around the rule; D peeks at everything. All three are what the underscores ask you not to do.

Encapsulation, in words

What is encapsulation?
Data inside, methods as the door. The rule "no negative balance" lives in deposit, and nothing outside can reach the balance another way. Not every attribute needs hiding, only the ones with rules.
What does the double underscore actually do to __balance?
Renames it. Name mangling folds the class name in. account.__balance finds nothing; account._BankAccount__balance still works. A strong convention, not a lock.
Abstraction, next to encapsulation: what is it?
Hiding the steps. Encapsulation hides the data; abstraction hides how the work is done. You have used it since Class 1: print hides a great deal.
Encapsulation: data inside, methods as the door. The double underscore renames, it does not lock. Abstraction: a simple name over hidden steps.

Inheritance, in words

What does class Manager(Employee) give Manager?
Everything, uncopied. Manager reaches Employee's methods through the parent link. One place to fix, every child gets the fix. DRY.
What does super().__init__(name, salary) do?
Runs the parent's setup on this object. One object, two setup steps. Leave the line out and name is never set: AttributeError on the first read.
Overriding means
Child first. Python looks in the child class, then the parent. The parent's version still exists; super().describe() can reach it.
A loop calls speak() on a Dog and a Robot. Must they share a parent?
No parent needed. Polymorphism in Python is "do you have the method?", not "who is your parent?". Inheritance is for sharing code, not for permission to call.
Inheritance reuses a parent's code. super() runs the parent's setup on the same object. Overriding: child first. Polymorphism: one call, each object answers its own way.
