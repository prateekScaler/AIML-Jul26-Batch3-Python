✋
reduce combines the first two, then that result with the next, and so on. Final total?

  • The import line. map and filter are built in. reduce is not: it lives in functools. Forgetting the import is the number one reduce mistake. Why the difference: next step.
product = reduce(lambda a, b: a * b, numbers, 1)
print(product)
24
  • A third argument is the starting value: what the running answer holds before the first item.
  • Without it, the first item is the start. With it, the start combines with the first item.
  • Pick a start that changes nothing: 0 for adding, 1 for multiplying. Then an empty list gives that start instead of an error.
A start of 100. What prints?
print(reduce(lambda a, b: a + b, [600, 250], 100))
950. 100 + 600 is 700, then 700 + 250 is 950. The start is the first running answer.
The wrong start. What prints?
print(reduce(lambda a, b: a * b, [2, 3], 0))
0. 0 × 2 is 0, 0 × 3 is 0. A start of 0 kills a product. For multiplying, start at 1, the number that changes nothing.

Why reduce is not built in

Real incident · 2005

The creator of Python moves reduce out of the way

  • In Python 2, reduce was a built-in next to map and filter.
  • In 2005 Guido van Rossum wrote that almost every reduce he saw made him stop and work out what it did; a plain loop or sum read better.
  • Python 3 moved it into functools. Still there, one import away, but no longer the first tool you reach for.
The language itself tells you something: map and filter read well, reduce often does not. For a total, sum(amounts) beats a reduce.
Read: Guido van Rossum, "The fate of reduce() in Python 3000" (2005) · Photo: Daniel Stroud, CC BY-SA 4.0, Wikimedia Commons · Python docs: functools.reduce

Two of these words run the internet

Real incident · 2004

Google names its web-scale engine after two functions

  • To index the whole web, Google needed thousands of machines to work on one job at once.
  • Jeffrey Dean and Sanjay Ghemawat split every job into the same two steps: map each page to (word, count) pairs, then reduce all the pairs for a word into one total.
  • They named the system MapReduce after the two functional-programming tools. Hadoop and most big-data systems copied the idea.
The pattern you learn today on a list of three numbers is the same pattern that counts every word on the web. Only the size changes.
Read: Google Research: MapReduce, Simplified Data Processing on Large Clusters (2004)

A class is a blueprint. An object is one thing built from it.

  • Class: the definition. What every account has, and what it can do.
  • Object, also called an instance: one real account, with its own numbers.
  • One blueprint, as many houses as you like.

        self.balance = balance
        self.pin = pin
        self.history = []

    def pay(self, upi_id, amount, mode="upi"):
        fee = self.fee_for(mode)
        if amount + fee > self.balance:
            print("Insufficient balance. Payment refused.")
            return

        self.balance = self.balance - amount - fee + cashback

        print(f"Paid ₹{amount} to {payee} via {mode_name(mode)}")

  • Fifty places in a program can set balance. One typo, one bad line, and the money is wrong.
  • The fix: put the data inside, mark it internal, and make the methods the only door.
class BankAccount:
    def __init__(self, balance):
        self.__balance = balance

    def get_balance(self):
        return self.__balance

    def deposit(self, amount):
        if amount > 0:
            self.__balance += amount

Inheritance: two questions

super() is missing. What happens on the last line?
class Employee:
    def __init__(self, name, salary):
        self.name = name
        self.salary = salary

class Manager(Employee):
    def __init__(self, name, salary, team_size):
        self.team_size = team_size

print(Manager("Chitransh", 90000, 5).name)
AttributeError. Manager's own __init__ replaced Employee's and never called it, so name was never set. The most common inheritance mistake: add super().__init__(name, salary).
No shared parent at all. Does the loop still work?
class Dog:
    def speak(self):
        return "Woof"

class Robot:
    def speak(self):
        return "Beep"

for thing in [Dog(), Robot()]:
    print(thing.speak())
Woof then Beep. Python's polymorphism only needs the method to exist on the object. No parent required. Inheritance is for sharing code, not for permission to call.

Debug clinic: the method that forgot itself

class Account:

        self.owner = owner

        print("Welcome, " + owner)

Account("Rajani").greet()

Debug clinic: the balance that nobody set

class Account:
    def __init__(self, owner, balance):
        self.owner = owner
        balance = balance

AttributeError: 'Account' object has no attribute 'balance'
  • balance = balance is a local variable that dies when __init__ ends. Only self.balance = balance stores it on the object.
