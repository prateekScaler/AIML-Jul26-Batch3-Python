Indentation is not decoration

✋
Same words. Only the spacing changed. What happens?

amount = 400

if balance >= amount:

Runs, different output
Fails with an error

  • Indentation tells Python which lines belong to the if.
  • It is part of the syntax. Convention: 4 spaces.
Indented = inside the decision. Not indented = outside it.
Real incident · 2014

Apple's security check that never ran

  • One line was pasted twice in Apple's connection-security code.
  • It was indented as if it belonged to an if. In that language, indentation means nothing. It ran every time.
  • So the security check below it was skipped on every iPhone and Mac.
if (check_1_failed)
    goto fail;
    goto fail;          // pasted twice. Looks inside the if. Is not.
if (check_2_failed)     // never reached
    goto fail;
Python makes indentation the truth. What you see is what runs.

Exact values: match / case

  • Choose what happens for each payment mode.
mode = input("Payment mode: ")

if mode == "upi":
    print("Opening UPI app...")
elif mode == "card":
    print("Enter card PIN")
elif mode == "netbanking":
    print("Redirecting to your bank")
else:
    print("Unknown mode")
  • Works. But every line asks the same thing: mode == ...
mode = input("Payment mode: ")

match mode:
    case "upi":
        print("Opening UPI app...")
    case "card":
        print("Enter card PIN")
    case "netbanking":
        print("Redirecting to your bank")
    case _:
        print("Unknown mode")
match mode:
Compare this variable against the cases below. Runs once.
case "upi":
Is mode exactly "upi"? Top to bottom, first match wins.
case _:
The wildcard. Anything left over. Plays the role of else.
match: one variable against exact values. Ranges like amount >= 5000 stay with if / elif.

Needs Python 3.10 or newer.

The user types UPI, in capitals. What prints?
Unknown mode. A case is an exact match, and text is case-sensitive: "UPI" is not "upi". Real apps clean the input first.
Which of these is the right job for match?
Payment mode. One variable, a few exact values. The other three are comparisons and ranges: if / elif / else.

Input → Condition → True or False → an action

A one-line decision

  • Five lines just to set one variable.
balance = 1000
amount = 400

if balance >= amount:
    status = "SUCCESS"
else:
    status = "FAILED"

print(status)
🎤
Guess: how might Python squeeze lines 4 to 7 into one line?
status = "SUCCESS" if balance >= amount else "FAILED"
value_if_true if condition else value_if_false
  • Read it as a sentence: status is SUCCESS if the balance is enough, else FAILED.
  • Called a conditional expression, or the ternary operator. Not new logic. A compact if / else that gives a value.
balance = 500, amount = 800. What prints?
status = "SUCCESS" if balance >= amount else "FAILED"
print(status)
FAILED. 500 >= 800 is False, so the value after else.
A dev swapped the two words. balance = 1000, amount = 400. What prints?
status = "FAILED" if balance >= amount else "SUCCESS"
print(status)
FAILED. The condition is True, and the value before if is the True value. Python runs it happily. A logic bug, not a syntax bug.

When not to use a ternary

Clever, unreadable
cashback = 100 if amount >= 5000 else 50 if amount >= 2000 else 10 if amount >= 500 else 0
Plain, readable
if amount >= 5000:
    cashback = 100
elif amount >= 2000:
    cashback = 50
elif amount >= 500:
    cashback = 10
else:
    cashback = 0
Ternary for a simple two-way choice. Three or more outcomes: if / elif / else.
A transaction fee, written the clever way. amount = 1000. What prints?
amount = 1000

fee = 0 if amount < 1000 else 5 if amount < 10000 else 10
print(fee)
5. Left to right: 1000 < 1000 is False, so look at the rest: 1000 < 10000 is True → 5. If it took a while to read, that is the point.
