Three patterns, three tools

Why is it called functional programming?

🎤
The word "function" is in the name. What do you think the style is about?
  • A style where functions are the main tool: you build a program by handing functions to functions.
  • A function is a value, like a number or a string. You can store it, pass it, return it.
  • Each function makes a new result and leaves its input alone. No variable is changed step by step.
The loop way (what we did so far)The functional way (today)
an empty list, a loop, append one at a timehand a rule to map: a new list comes back
an if inside the loop decides what to keephand a rule to filter
a running total, changed on every turnhand a combining rule to reduce
variables change as the loop runsnothing changes; new values are made
  • Everything today fits that one idea: lambda writes a small function value, higher-order functions take one, map, filter, reduce and sorted apply it.
  • Python is not a pure functional language. It lends you the style where it reads well, and keeps loops for the rest.

  • A function that takes a function, or returns one, is a higher-order function. map, filter and reduce are all three.
Higher-order function: a function that takes a function as an argument (or returns one, next class). "Higher" because it works on functions, not only on data. apply_twice is one; so are map, filter, reduce and sorted.

map: the same change to every item

numbers = [1, 2, 3, 4]

squared = map(lambda x: x ** 2, numbers)
  • Two arguments: the function to apply, and the list to apply it to.
  • Read it as "map this change over these numbers".
✋
The vote of the class. What does print(squared) show?
print(squared)
[1, 4, 9, 16]
(1, 4, 9, 16)
Something else entirely
<map object at 0x102f17740>
  • Nothing has been squared yet. map hands back a promise: "I will square them, one at a time, when someone asks."
  • This is called lazy evaluation. The address in the message changes every run; the type does not.
  • Why lazy? map works one item at a time, only when asked. It never builds the whole list in memory.
  • Why it matters: a million numbers, a file of a million lines, a stream that never ends: map can walk them without storing them all.
  • The price: nothing happens until something asks. Printing is not asking.
A million numbers. After this line, how many squares has Python computed?
squared = map(lambda x: x ** 2, range(1_000_000))
Zero. The line only sets the promise up. list(squared) would compute all million; for x in squared: computes one per turn of the loop.

Ask for the values: list()

print(list(squared))
[1, 4, 9, 16]
  • list() asks the promise for every value and collects them.
  • A for loop asks too. Printing does not.
Anything that walks a collection can asksquared = map(lambda x: x ** 2, [1, 2, 3, 4])
list(squared)[1, 4, 9, 16]

sum(squared)30

What prints?

[1, 4, 9] then []. A map object hands out each value once. After the first list, it is empty. Need the values twice? Store the list: squared = list(map(...)).

✋
You know map now. What type comes back, and what is in the final list?

reduce: combine everything into one value

✋
reduce combines the first two, then that result with the next, and so on. Final total?
from functools import reduce

numbers = [1, 2, 3, 4]

total = reduce(lambda a, b: a + b, numbers)
print(total)
10
[3, 5, 7]
24
10
  • The import line. map and filter are built in. reduce is not: it lives in functools. Forgetting the import is the number one reduce mistake.
  • What is functools? A module: a file of ready-made Python functions that ships with Python. functools holds tools for working with functions.
  • Python keeps most of its tools in modules so the language itself stays small. math has sqrt, random has randint, functools has reduce.
  • from functools import reduce brings one name in. A package is a folder of modules; you meet both properly in Class 13.

Why the splitPython keeps the always-needed few at hand and the rest in modules, so a small script starts fast and the names stay few.
product = reduce(lambda a, b: a * b, numbers, 1)
print(product)
24
  • A third argument is the starting value: what the running answer holds before the first item.
  • Without it, the first item is the start. With it, the start combines with the first item.
  • Pick a start that changes nothing: 0 for adding, 1 for multiplying. Then an empty list gives that start instead of an error.
A start of 100. What prints?
print(reduce(lambda a, b: a + b, [600, 250], 100))
950. 100 + 600 is 700, then 700 + 250 is 950. The start is the first running answer.
The wrong start. What prints?
print(reduce(lambda a, b: a * b, [2, 3], 0))
0. 0 × 2 is 0, 0 × 3 is 0. A start of 0 kills a product. For multiplying, start at 1, the number that changes nothing.
No payments yet. What prints?
amounts = []
print(reduce(lambda a, b: a + b, amounts, 0))
print(reduce(lambda a, b: a + b, amounts))
0 then TypeError. With a start, an empty list gives the start back. Without one, there is nothing to begin from: TypeError: reduce() of empty iterable with no initial value. A statement with no payments yet is exactly this case.

Why reduce is not built in

Real incident · 2005

The creator of Python moves reduce out of the way

  • In Python 2, reduce was a built-in next to map and filter.
  • In 2005 Guido van Rossum wrote that almost every reduce he saw made him stop and work out what it did; a plain loop or sum read better.
  • Python 3 moved it into functools. Still there, one import away, but no longer the first tool you reach for.
The language itself tells you something: map and filter read well, reduce often does not. For a total, sum(amounts) beats a reduce.
Read: Guido van Rossum, "The fate of reduce() in Python 3000" (2005) · Python docs: functools.reduce
What prints?
from functools import reduce
print(reduce(lambda a, b: a if a > b else b, [600, 1500, 250]))
1500. Each step keeps the bigger of the two, so the biggest survives. max(amounts) does the same, and says so.
The import is missing. What happens?
total = reduce(lambda a, b: a + b, [1, 2, 3])
print(total)
NameError. Python does not know the word. from functools import reduce first.

Two of these words run the internet

Real incident · 2004

Google names its web-scale engine after two functions

  • To index the whole web, Google needed thousands of machines to work on one job at once.
  • Jeffrey Dean and Sanjay Ghemawat split every job into the same two steps: map each page to (word, count) pairs, then reduce all the pairs for a word into one total.
  • They named the system MapReduce after the two functional-programming tools. Hadoop and most big-data systems copied the idea.
The pattern you learn today on a list of three numbers is the same pattern that counts every word on the web. Only the size changes.
Read: Google Research: MapReduce, Simplified Data Processing on Large Clusters (2004)

🎤
Three payments, each a tuple. By name, by amount or by mode: how do we tell sorted which one?

Three tuples. The key says "look at position 1". What comes first?
payments = [("Hitender", 600, "upi"),

  • The key is a function. sorted is a higher-order function too.
biggest_first = sorted(payments, key=lambda p: p[1], reverse=True)
print(biggest_first[0])

print(max(payments, key=lambda p: p[1]))
('Prajnika', 1500, 'upi') ('Prajnika', 1500, 'upi')

sorted: two questions

What prints?
names = ["Prajnika", "Sumit", "Hitender"]
print(sorted(names, key=lambda n: len(n)))
Sumit, Prajnika, Hitender. Sorted by length: 5, 8, 8. Prajnika and Hitender tie, and a tie keeps the original order. The key is only used for comparing; the names themselves come back.
What prints?
payments = [("A", 600), ("B", 250)]
payments.sort(key=lambda p: p[1])
result = sorted(payments, key=lambda p: p[0])
print(payments[0], result[0])
('B', 250) ('A', 600). sort changed the list in place, by amount, so B is first. sorted made a new list by name, so A is first there, and left payments alone. Class 6, with a key.

When a lambda, when a def

  • Every lambda today was written inside the call and used once. That is the point: logic needed once, right there, no name to invent.
The logicWriteWhy

Which one is a SyntaxError?
The one with return. A lambda is the expression; the return is built in. Writing it is an error. The no-parameter lambda is fine.

PaisaPay v10: the statement, with today's tools

PaisaPay v10 · one build
The ₹500 rule is a stored lambda. Then the statement: map for the amounts, reduce for the total, filter for the big payments, sorted with a key for the biggest and for the order.
is_big = lambda payment: payment[1] >= 500

def mini_statement(history):
    if len(history) == 0:
        print("No payments yet.")
        return
    amounts = list(map(lambda p: p[1], history))
    total = reduce(lambda a, b: a + b, amounts)
    big = list(filter(is_big, history))
    biggest = sorted(history, key=lambda p: p[1], reverse=True)[0]
    print(f"Payments: {len(history)} | Spent ₹{total}")
    print(f"Big payments (₹500 or more): {len(big)}")
    print(f"Biggest: ₹{biggest[1]} to {biggest[0]}")
    for name, amount, mode in sorted(history, key=lambda p: p[1]):
        print(f"  ₹{amount} {name} ({mode_name(mode)})")
