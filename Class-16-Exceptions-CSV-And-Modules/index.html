Before we open one: what does CSV stand for?

🎤
Banks, Excel and Google Sheets all export .csv files. Take a guess.
CSV is short for:
Comma-Separated Values. Each line is one row, and a comma separates the values in it. "Character-separated" is close: some files use a tab or a semicolon instead, but the name says comma.
C for Comma, S for Separated, V for Values.

What if you forget newline=""?

🎤
What if we leave out newline="", and a classmate runs it on Windows?
The same three rows, opened in a spreadsheet.
\n
line feed, also called newline: move down to the next line
\r
carriage return: go back to the start of the line. The name comes from typewriters, where the carriage slid back to the left
\r\n
Windows ends every line with both. Mac and Linux use only \n
A typewriter needed both moves to start a new line. Windows still writes both: \r\n.
Two line endings in a row read as an empty line. newline="" tells Python: do not add your own.
  • Why only Windows? When a program writes text, Python changes every \n into the line ending of that computer.
ComputerIts line endingcsv writesPython changes \n toIn the file
Mac, Linux\n\r\n\n (no change)\r\n: fine
Windows\r\n\r\n\r\n\r\r\n: an empty row
Any, with newline=""\r\nnothing: the change is switched off\r\n: fine
  • So on a Mac or Linux the bug hides. It shows up on a Windows laptop, or when the file reaches Excel.
  • Read back in Python, the empty rows arrive as empty lists: [['payee', 'amount'], [], ['Sumit', '600'], [], ...]. A loop that does int(row[1]) then crashes with IndexError.

import csv

def analyze_visits(filename):
    try:
        with open(filename, "r") as file:
            reader = csv.DictReader(file)
            rows = list(reader)
    except FileNotFoundError:
        print(f"Error: {filename} not found.")
        return

    total = len(rows)
    errors = [r for r in rows if int(r["status_code"]) >= 400]

    print(f"Total requests: {total}")
    print(f"Errors: {len(errors)}")

    with open("summary.txt", "w") as file:
        file.write(f"Total requests: {total}\n")
        file.write(f"Errors: {len(errors)}\n")

Debug clinic: the file that hid a module

  • Your folder has two files: game.py, and your own random.py.
# game.py
import random

print(random.randint(1, 6))
AttributeError: module 'random' has no attribute 'randint' (consider renaming '.../random.py' since it has the same name as the standard library module named 'random' and prevents importing that standard library module)
  • Python found your random.py first, and it has no randint.
  • Fix: rename your file, for example to my_random.py. Python 3.13 and newer even suggest it in the message.
Never name a file after a module you use.

Two minutes. Three points you would tell a friend who missed today.
  • try / except: try the risky part; except runs only if its named error happens, then the program goes on.
  • Name the error. With several excepts, the one that matches the kind of error runs. A bare except: hides bugs.
  • CSV: a table as text. csv.reader gives lists, csv.DictReader gives dictionaries keyed by the header.
  • Every CSV value is a string. Convert with int(). Write with newline="".
  • Modules: any .py file can be imported. The standard library is already installed. Never name a file after a module.
