A payment of ₹99.90 is recorded like this. What prints?
print(int(99.9))
99. Ninety paise vanished.
  • 99.9 is already a number (a float). On a number, int() converts by cutting off the decimals. It does not round.
  • On text, int() is strict: int("99.9") is a ValueError, because text must be a whole number in digits.
  • Text with a dot needs two steps: int(float("99.9")) gives 99.
The amount arrives as text with a dot. Two conversions. What prints?
amount = "99.9"
print(int(float(amount)))
99. Inside out: float("99.9") accepts the dot and gives the number 99.9. Then int(99.9) cuts to 99. Text to number first, then number to whole number.
Now the other direction: numbers turned into text. What prints?
print(str(250) + str(50))
25050. str() turns each number into text, and + joins text. Casting works in both directions, and the direction decides what + means.
print(0.1 + 0.2)
0.30000000000000004
Why? It happens to you in decimal too
1 / 3 = 0.333… never ends  →  cut it: 0.33  →  0.33 + 0.33 + 0.33 = 0.99
  • A computer counts in binary: only 0 and 1.
  • In binary, 0.1 never ends, like 1/3 in decimal. The computer must cut somewhere.
print(0.1 + 0.2)
print(0.1 * 3)
0.30000000000000004 0.30000000000000004
  • Each float is off by a tiny bit. Add a few and the error shows.
  • Tiny errors × crores of transactions = real money.
  • So payment systems store money as an int of paise. Razorpay: ₹299 is sent as 29900.
Money is an int of paise, never a float of rupees.

Which operator goes first?

✋
Commit to a number.
result = 10 + 5 * 2
print(result)
30
20
  • Multiplication first: 5 × 2 = 10. Then 10 + 10 = 20.
Python follows a fixed order, called operator precedence.
1 · Parentheses ( )
2 · Power **
3 · * / // %
4 · + -
5 · Comparisons == != > < >= <=
6 · not
7 · and
8 · or
Is this BODMAS?
  • Yes, for the maths part. Python then keeps going.
BODMAS at schoolPython
BracketsParentheses ( )
Orders (powers, roots)Power **
Division, Multiplication* / // %, same level, left to right
Addition, Subtraction+ -, same level, left to right
Stops hereThen comparisons, then not, and, or
  • Same level means left to right: 10 - 4 - 3 is 3, not 9. Maths uses the same convention. BODMAS only looks like “D before M, A before S”; a maths teacher does 20 ÷ 2 × 5 left to right too, and gets 50.
  • One exception, in both maths and Python: powers go right to left. 2 ** 3 ** 2 is 2 to the power 9, which is 512.
  • Python has operators school never had: //, %, and the whole True/False family after the maths.

Parentheses say exactly what to calculate first. They help the human reader too.
Two friends paid ₹100 and ₹200. A program prints their average. What prints?
print(100 + 200 / 2)
200.0. Division first: 200 / 2 = 100.0, then 100 + 100.0. The average needs (100 + 200) / 2.
  • Why 200.0 and not 200? Mixing an int with a float gives a float. Python turns 100 into 100.0 first, because nothing is lost that way.
  • Rules: int with int stays int (except /). Any float in the mix makes the result a float. / always gives a float.
Three conditions, no parentheses. What prints?
print(True or False and False)
True.
1 · and goes before or, so Python groups it as True or (False and False)
2 · Inside the group: False and False → False
3 · Then: True or False → True
Read it the other way, (True or False) and False, and you get False. Same words, opposite answer.
When you mix and with or, write the parentheses.
