OOP recap: the ideas

PaisaPay has 50 accounts. Why write one class instead of 50 sets of variables?
One blueprint, many objects. Each account keeps its own data, and every account shares the same methods. Fix a method once, and all 50 accounts get the fix.
Class 11: the class is the blueprint.
After a = Account("Rajani", 1000), what is a?
An object. Account is the blueprint. Calling it builds one object, and __init__ fills in its data.
Calling the class builds an object.
bank = "PaisaPay" is written in the class body. self.balance = balance is written in __init__. Which is right?
Where it is written decides. In the class body: one value for all objects, a class variable. On self: each object's own, an instance (object) variable.
Class variable versus instance variable.
Why is the balance written self.__balance, changed only through deposit() and pay()?
Encapsulation. The data stays inside, and the methods are the door. The rule "no negative amount" lives in one place and cannot be skipped by mistake.
Data inside, methods as the door.
deposit is written once, in the class. Rajani and Sumit both call it. How does it change only the right balance?
self. rajani.deposit(500) runs deposit with self = rajani. One method, the right object every time.
The object before the dot becomes self.

OOP recap: predict the output

The class variable is changed on the class. What prints?
class Account:
    bank = "PaisaPay"

    def __init__(self, owner):
        self.owner = owner

a = Account("Rajani")
b = Account("Sumit")
Account.bank = "PaisaPay Plus"
print(a.bank, b.bank)
Both change. There is one bank, kept in the class. Every object reads it from there.
Change the class variable, every object sees it.
Now the change is made on one object. What prints?
class Account:
    bank = "PaisaPay"

    def __init__(self, owner):
        self.owner = owner

a = Account("Rajani")
b = Account("Sumit")
a.bank = "OtherPay"
print(a.bank, b.bank, Account.bank)
Only a changes. a.bank = ... makes a new instance variable on a, which hides the class one. b and the class still say PaisaPay.
Assigning on an object makes an instance variable.
What happens on the last line?
class Account:
    def __init__(self, balance):
        self.__balance = balance

    def get_balance(self):
        return self.__balance

acc = Account(1000)
print(acc.get_balance())
print(acc.__balance)
AttributeError. Inside the class the name is renamed, name mangling. Outside, read it through the door: get_balance() printed 1000 on the line before.
Encapsulation at work.
One method, two objects. What prints?
class Account:
    def __init__(self, owner, balance):
        self.owner = owner
        self.balance = balance

    def deposit(self, amount):
        self.balance += amount

rajani = Account("Rajani", 1000)
sumit = Account("Sumit", 2500)
rajani.deposit(500)
print(rajani.balance, sumit.balance)
1500 2500. self was rajani, so only Rajani's balance changed. Sumit's object was never touched.
Each object keeps its own data.

Which tool: a string method, a regex, or an LLM?

  • For each job, pick the simplest tool that works.
Does a file name end in .csv?
A string method. name.endswith(".csv") is exact text: simplest, fastest, clearest.
Pull the six-digit OTP out of each of 10,000 SMS messages, fast and free.
A regex. \d{6} is a fixed shape. It runs on your machine in a moment and gives the same answer every time.
A customer writes "paise kat gaye par recharge nahi hua". Is it a failed-recharge complaint?
An LLM. This is meaning, in any words and any language. No pattern lists every way to say it.
A scanned letter, typed messily, has the customer's PAN somewhere in it. You must store a correct PAN.
Both. The LLM finds the PAN in messy text. A regex, [A-Z]{5}\d{4}[A-Z], then checks the answer, because an LLM can be wrong.

Which tool? Three more

Is this a valid IFSC code: four capitals, a 0, then six letters or digits?
A regex. A fixed shape: [A-Z]{4}0[A-Z0-9]{6} with fullmatch.
Sort 500 customer reviews into happy, angry and confused.
An LLM. Mood is meaning. Words such as "great" can be angry too: "great, it failed again".
A line from a file reads Sumit,600,UPI. You need the three parts.
A string method. line.split(",") gives the three parts. A regex works, but is harder to read for no gain. For full CSV files, the csv module.
Exact text: a string method. A shape: a regex. A meaning: an LLM. And check an LLM's answer when it must be right.

Inheritance, in words

  • Account is a parent class. PremiumAccount inherits from it, so it is a child class.
class Account:                  # the parent
    def total(self, amount, mode):
        ...

class PremiumAccount(Account):  # the child: inherits from Account
    pass
class PremiumAccount(Account): the name in brackets is the parent.
The child, PremiumAccount, has no total method. You call premium.total(1000, "card"). Where does Python find it?
Child first, then parent. Nothing is copied. Python looks in the object's own class, then walks up to the parent. 
class Account:
    def total(self, amount, mode):
        fee = 5 if mode == "card" else 0
        return amount + fee

class PremiumAccount(Account):
    pass                       # no total here

premium = PremiumAccount()
print(premium.total(1000, "card"))
1005

PremiumAccount wrote no total, yet the call works: Python found it in Account.

Look in the child, then the parent.

Scenario: a parent method calls an overridden method

✋
total is written once, in Account. Two objects call it. What prints?
class Account:
    def fee_for(self, mode):
        return 5 if mode == "card" else 0

    def total(self, amount, mode):
        return amount + self.fee_for(mode)

class PremiumAccount(Account):
    def fee_for(self, mode):
        return 0

print(Account().total(1000, "card"))
print(PremiumAccount().total(1000, "card"))
1005 then 1005
1005 then 1000
1000 then 1000
1005 1000
  • The same total method, two answers. self decides which fee_for runs.
  • PaisaPay v13 uses exactly this: pay() is in Account, and a PremiumAccount pays no fee.
Write the rule once in the parent. Let each child change one piece.

Scenario: a child class variable with the same name

✋
Each class sets its own rate. What prints?
class Deposit:
    rate = 4

class FixedDeposit(Deposit):
    rate = 7

print(Deposit.rate, FixedDeposit.rate, FixedDeposit().rate)
4 4 4
7 7 7
4 7 7
4 7 7
  • The child's rate hides the parent's. The parent's 4 does not change.
  • An object of FixedDeposit finds 7 first, so it never looks at Deposit.
The nearest class wins.

Scenario: super().__init__ with one argument short

✋
Intern passes only the name up to Employee. What happens?
class Employee:
    def __init__(self, name, salary):
        self.name = name
        self.salary = salary

class Intern(Employee):
    def __init__(self, name):
        super().__init__(name)

Intern("Karthikeyan")
Nothing: salary becomes None
AttributeError: 'Intern' object has no attribute 'salary'
TypeError: Employee.__init__() missing 1 required positional argument: 'salary'
TypeError: Employee.__init__() missing 1 required positional argument: 'salary'
  • super().__init__ calls the parent's __init__. It still needs every argument the parent asks for.
  • Fix: pass a value, for example super().__init__(name, 0).
The parent's rules still apply.
