Revision: four short forms we rushed past

  • Python often has a long way and a short way. Same result, fewer lines.
  • The long way is always correct. The short way is a habit you grow into.
Four short forms, one each from Classes 3, 4, 6 and 5. Fifteen minutes.

Short form 1: the ternary, one decision in one line

balance = 300

if balance >= 500:
    status = "OK"
else:
    status = "LOW"

print(status)
🎤
Four lines to put one of two words in a variable. Read the short way out loud.
status = "OK" if balance >= 500 else "LOW"
print(status)
LOW
Read it as English: status is OK if the balance is at least 500, else LOW.
Why is it called a ternary?
  • Latin ternarius: made of three. It takes three parts: a value, a question, another value.
  • Most operators take two parts, like a + b. This is Python's only three-part operator.
Which of these should not be a ternary?
The grade. Four outcomes. A ternary is for two. Chained ternaries read badly after the second; write if / elif. The other three are one two-way choice each.
What prints?
amount = 1000
label = "Big" if amount >= 1000 else "Small"
print(label)
Big. 1000 is at least 1000, so the value before if is chosen.
Which line is the correct ternary for this?
if amount > 2000:
    fee = 5
else:
    fee = 0
The second. Value first, then if the question, then else the other value. The first puts if first, the third is another language, the last has no else. All three are SyntaxErrors.
Which line is the correct ternary for this?
if pin == saved_pin:
    print("Access granted")
else:
    print("Wrong PIN")
The third. The ternary chooses the text; the print shows it. The first chooses but never prints. The second and fourth are SyntaxErrors.

Short form 2: for item in list

amounts = [600, 300, 1500]

i = 0
while i < len(amounts):
    print(amounts[i])
    i += 1
🎤
A counter, a condition, an index, an increment. Which of those do we actually care about?
for amount in amounts:
    print(amount)
600 300 1500
Python hands you each box in turn. No counter, no index, no off-by-one.
Why is it called for?
  • Say it as English: for each amount in amounts, do this. The word is the English word.
  • It is the same for as for i in range(5). A range is just another sequence of values.
Which task fits for item in list best?
The reminders. One action per item, no position needed. The PIN is a while; position and name need range(len(…)); five times is range(5).
How many lines print?
payees = ["Chai Point", "Zomato", "Jio", "Uber"]
for payee in payees:
    print("Reminder sent to", payee)
4. One pass per box, and the list has four boxes.
We double every amount. What does the list hold afterwards?
amounts = [600, 300]
for amount in amounts:
    amount = amount * 2
print(amounts)
Unchanged. amount is a copy of the box's value. Changing the copy does not touch the list. To build doubled values, make a new list: the next short form.

Short form 3: a new list in one line

amounts = [600, 300, 1500]

doubled = []
for amount in amounts:
    doubled.append(amount * 2)

print(doubled)
🎤
Start empty, walk, append. Say what the new list should contain in one sentence.
doubled = [amount * 2 for amount in amounts]
print(doubled)
[1200, 600, 3000]
Three parts. The third is optional. The whole thing is one expression that gives back a new list.
Behind the scenes: each box goes through the gate, the survivors are transformed, the results fill a new list. Same as the loop, one item at a time.
What prints?
print([x * x for x in range(4)])
[0, 1, 4, 9]. range(4) is 0 to 3, and each is squared.
Why is it called a comprehension?
  • From mathematics. A set written by its rule, not by listing its members: “the set of all x × 2 for x in amounts”. Mathematicians call that set-builder notation, or comprehension.
  • Python borrowed the idea and the name: describe the list by its rule, and Python builds it.
  • Not “comprehension” as in understanding. Think “comprehensive”: the whole list, stated in one rule.
  • Is it syntactic sugar? Yes.
  • Sugar: a shorter way to write what the language could already do.
  • Every comprehension is the loop above. Same list, shorter to read.
Which of these should stay a normal loop?
The second. It prints, counts and appends: three jobs and a side effect. A comprehension does one job: build a list. The other three are make, keep, make.
Which line is the correct comprehension for this loop?
scores = [35, 72, 45]
bonus = []
for s in scores:
    bonus.append(s + 5)
The second. Make first (s + 5), then from (for s in scores). The first and last put the pieces in the wrong order; the third has no for at all, so s does not exist there: NameError.
Now with a condition. Which line is the correct comprehension?
amounts = [600, 300, 1500]
big = []
for a in amounts:
    if a >= 500:
        big.append(a)
The third. Make, from, keep: the filter goes last. The second runs but builds [True, False, True]: it makes a bool for every item instead of keeping some. The first and last are SyntaxErrors.
Behind the scenes: each box goes through the gate, the survivors pass through unchanged, the results fill a new list. Same as the loop, one item at a time.
Make, from, keep. What prints?
words = ["upi", "card", "netbanking", "cash"]
print([w.upper() for w in words if len(w) > 3])
Three words in capitals. Keep the words longer than 3 letters, then upper-case each kept one. "upi" has exactly 3, so it is dropped.
What prints?
amounts = [600, 300, 1500]
big = [a for a in amounts if a >= 500]
print(len(big), len(amounts))
2 3. A comprehension builds a new list and never changes the source.

Short form 4: lambda, a tiny function without a name

def cashback(amount):
    return amount * 5 // 100

print(cashback(1000))
🎤
One line of logic, three lines of ceremony. When is the name worth having?
cashback = lambda amount: amount * 5 // 100
print(cashback(1000))
50
A machine with no nameplate. You usually hand it to another function instead of storing it.
Why is it called lambda?
  • From the Greek letter λ. In the 1930s the logician Alonzo Church wrote functions without names as λx. x × 2. Python kept the word.
  • So a lambda is a function with no name of its own.
  • You hand it to another function: sorted and filter take one in Class 9.
Which line is the correct lambda for this function?
def fee(amount):
    return amount * 2 // 100
The first. Parameters after the word lambda, no brackets, a colon, then the expression. No return word: the expression is the return value. The second and third are SyntaxErrors; the last takes no parameter, so fee(1000) is a TypeError.
No parameters this time. Which line is the correct lambda?
def welcome():
    return "Welcome to PaisaPay"
The last. No parameters means nothing between lambda and the colon, but the colon stays. The first has brackets, the second has no colon: SyntaxErrors. The third runs, but it prints instead of returning, so welcome() gives back None: the Class 5 trap.
Which of these should not be a lambda?
The PIN check. Three statements, a side effect and a name people will call again: that is a def. A lambda holds one expression and nothing else. The other three are one expression each.
What prints?
area = lambda a, b: a * b
print(area(3, 4))
12. Two parameters, one expression, no return word needed.
A ternary inside a lambda. What prints?
kind = lambda n: "even" if n % 2 == 0 else "odd"
print(kind(7), kind(10))
odd even. The lambda's one expression is a ternary. 7 is odd, 10 is even. Two short forms in one line.

title and strip

name = "   rashi sharma   "

print(name.title())
print(name.strip())

  • title(): a capital at the start of every word.
  • A word, to title, is any run of letters. It restarts at a space, hyphen, apostrophe or digit.
  • So "rashi-sharma" → "Rashi-Sharma", and "it's" → "It'S".
  • strip(): spaces removed from both ends only. The space between the words stays.
  • Chain them. Each method hands back a string, and the next method works on that.

# PaisaPay v7: text in, text out
print("Welcome to PaisaPay")

saved_pin = "4321"
history = []

def clean(text):
    return text.strip().lower()

def is_valid_amount(amount):
    return amount > 0 and amount <= 100000

def is_valid_pin(pin):
    return pin == saved_pin

def is_valid_upi_id(upi_id):
    parts = upi_id.split("@")
    return len(parts) == 2 and len(parts[0]) > 0 and len(parts[1]) > 0

def mask(card):
    return "**** **** **** " + card[-4:]

def fee_for(mode):
    if mode == "card":
        return 5
    elif mode == "netbanking":
        return 2
    return 0

def cashback_for(amount):
    if amount >= 5000:
        return 100
    elif amount >= 2000:
        return 50
    elif amount >= 500:
        return 10
    return 0

def mode_name(mode):
    match mode:
        case "upi":
            return "UPI"
        case "card":
            return "Card"
        case "netbanking":
            return "Net banking"
        case _:
            return "Unknown mode"

def print_receipt(name, amount, mode, fee, cashback, balance):
    print(f"Paid ₹{amount} to {name} via {mode_name(mode)}")
    print(f"Fee ₹{fee} | Cashback ₹{cashback} | Balance ₹{balance}")

def ask_pin():
    for attempt in range(3):
        pin = input("UPI PIN: ").strip()
        if is_valid_pin(pin):
            return True
        print(f"Wrong PIN. {2 - attempt} attempts left")
    return False

def pay(balance, history, upi_id, amount, mode="upi"):
    if not is_valid_upi_id(upi_id):
        print(f"'{upi_id}' is not a valid UPI ID. Payment refused.")
        return balance
    if not is_valid_amount(amount):
        print("Invalid amount. Payment refused.")
        return balance
    if mode_name(mode) == "Unknown mode":
        print(f"Unknown payment mode '{mode}'. Payment refused.")
        return balance
    fee = fee_for(mode)
    if amount + fee > balance:
        print("Insufficient balance. Payment refused.")
        return balance
    cashback = cashback_for(amount)
    balance = balance - amount - fee + cashback
    name = upi_id.split("@")[0].title()
    print_receipt(name, amount, mode, fee, cashback, balance)
    history.append(amount)
    return balance

def mini_statement(history):
    if len(history) == 0:
        print("No payments yet.")
        return
    total = 0
    for amount in history:
        total += amount
    print(f"Payments: {len(history)} | Spent ₹{total}")
    print(f"Biggest ₹{sorted(history)[-1]} | Last five: {history[-5:]}")

    elif choice != "4":

A word is not nothing

Real incident · 2019

The NULL number plate

  • A man in California chose the car number plate NULL. In many computer systems the word NULL means “nothing here”.
  • So every fine with a missing plate number was sent to him. At one point he owed $12,049 for other people's tickets.
  • The website that renews plates also treated his plate as empty, and refused him.
The text NULL is four letters. An empty value is a different thing. Keep them apart.
